## 每层放什么

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `01-需求` | 产品定位、范围边界、里程碑、风险、全局决策记录 | 具体功能的实现细节 |
| `02-架构` | 跨功能的工程契约：进程模型、任务状态机、IPC、存储、错误模型、并发 | 单个工具的路径规则 |
| `03-功能` | 一个功能（F1、F2…）从入口到验收的完整设计 | 跨功能复用的契约（引用 `02-架构`） |
| `04-设计` | UI 信息架构、页面规格、设计令牌、文案 | 业务规则本身 |
| `05-发布` | 打包、签名、分发、更新策略与异常处理 | 开发期构建细节（见 `README.md`） |

## 文档约定

- **决策只写一次**：同一条决策只在一份文档里写全文，其它文档只留编号（如 `D-F1-18`）。冲突时以《需求与方案设计》第 8 节为准；细节以独立文档为准。
- **文件名保持稳定**：文件名不随版本号变化，版本写在正文首行的引用块里；改版时同步更新本索引表格的「版本」列。
- **不新增平铺文件**：新文档放进对应分层目录；新增一层（如 `06-运维`）时，同时更新本索引的「阅读顺序」和「每层放什么」。
- **图片与附件**：如确需放图片，放在文档同级的 `assets/` 子目录，避免污染分层结构。

## 维护检查

改动文档后，至少确认：

1. 本索引里的链接与版本号与实际文件一致；
2. 根目录 [`README.md`](../README.md) 的「文档」表格指向本索引，而不是直接列文件路径；
3. 被移动 / 改名的文档没有留下失效引用（用 `grep -rn '](.*\.md'` 全仓查一遍）。
